Self-Improving

Constant Improvement Cycle

The framework learns from every manual QA correction, producing smarter V2 feature files each iteration

🤖 Step 1: Framework Generates V1 Feature File

AI-powered generation creates the first version of the Gherkin feature file from Jira work item requirements, acceptance criteria, and the knowledge base. Produces positive, negative, and edge case scenarios.

↓

📝 Step 2: QA Reviews & Updates V1

Manual QA engineer reviews the generated V1 feature file. Corrects scenarios, adds missing edge cases, refines step definitions, adjusts test data, and improves coverage based on domain expertise.

↓

🔎 Step 3: Framework Detects Changes

V2 detection utility (detect-v2-features) automatically identifies what QA changed between V1 and the manually updated version. Analyzes patterns, corrections, and improvements made by the QA engineer.

↓

📚 Step 4: Knowledge Base Updated

Learnings from QA corrections are fed back into the knowledge base (knowledge:build). Domain rules, field patterns, validation logic, and best practices are captured and stored for future use.

↓

🌟 Step 5: Smarter V2 Feature Files

Next time the framework generates feature files, it uses the enriched knowledge base to produce better, more accurate V2 versions — requiring fewer manual corrections each cycle. The framework gets smarter with every iteration.

↺ Continuous Learning Loop — Every QA Review Makes the Framework Smarter
