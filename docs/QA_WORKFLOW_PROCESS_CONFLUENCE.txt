h1. QA Test Case Review and Execution Workflow

h2. Overview
This document outlines the standard workflow for reviewing, approving, and executing test cases generated by the automation framework. This process ensures quality and traceability from Jira work items through test execution to final sign-off.

----

h2. Workflow Steps

h3. Phase 1: Initial Review and Approval

h4. Step 1: Start with Work Item
* *Action*: Select any Jira work item that is in *"In QA"* status
* *Purpose*: Begin the QA review process for items ready for testing

h4. Step 2: Review Requirements and Test Cases
* *Action*: Review both:
** Requirements documented in the Jira work item
** Test cases automatically created by the framework
* *Note*: Test cases are already linked to the work item
* *Purpose*: Ensure test cases align with requirements and cover all necessary scenarios

h4. Step 3: Approve Test Cases (If Satisfactory)
* *Condition*: If test cases meet quality standards and cover requirements
* *Action*: Update test case status from *"Draft"* to *"Approved"*
* *Location*: Test case details page in Zephyr Scale (or your test management tool)

*How to Update Status:*
# Open the test case details page
# Locate the *"Status"* dropdown field
# Change status from *"Draft"* to *"Approved"*
# Save the changes

*Available Statuses:*
* *Draft* - Initial status for newly created test cases
* *Approved* - Test cases reviewed and ready for execution
* *Deprecated* - Test cases no longer valid

----

h3. Phase 2: Test Case Updates (If Required)

h4. Conditional Step: Update Test Cases
* *Condition*: If test cases need modifications or updates
* *Action*:
## Create or edit the test case as needed
## Update the corresponding feature file
## *Important*: Append *"-v2"* to the feature file name for versioning
*** Example: {{MRD-FLS-Account.feature}} → {{MRD-FLS-Account-v2.feature}}
* *Purpose*: Maintain version control and track test case iterations

----

h3. Phase 3: Execution and Sign-Off

h4. Step 1: Execution Review / Manual Execution
* *Action*:
** Review automated execution results (if available)
** OR perform manual execution for new/updated test cases
* *Purpose*: Verify test cases execute correctly and produce expected results

h4. Step 2: Sign-Off (If Execution Results are Satisfactory)
* *Condition*: If execution results meet expectations
* *Action*: Provide sign-off with details as specified in the test plan document
* *Note*: Reference the test plan document for specific sign-off requirements
* *Purpose*: Document approval and readiness for next phase

h4. Step 3: Update Jira Work Item Status
* *Action*: Update the work item status in Jira to *"Ready for UAT"*
* *Purpose*: Move the work item to the next phase in the development lifecycle

----

h2. Test Case Details Fields

When reviewing or updating test cases, you may encounter the following fields:

||Field||Description||Example Values||
|*Status*|Current status of the test case|Draft, Approved, Deprecated|
|*Priority*|Priority level of the test case|Normal, High, Critical|
|*Estimated Run Time*|Expected execution duration|hh:mm format (e.g., 00:15)|
|*Component*|Associated component or module|None, Account, Contact, etc.|
|*Folder*|Organizational folder location|None, or specific folder path|
|*Tags*|Test case identifiers or labels|-001, given-a, etc.|

----

h2. Best Practices

# *Always Review Before Approval*
** Ensure test cases align with requirements
** Verify test coverage is adequate
** Check for any missing scenarios

# *Version Control*
** Use "-v2", "-v3", etc. when updating feature files
** Maintain clear version history
** Document reasons for updates

# *Execution Verification*
** Review execution results thoroughly
** Document any issues or discrepancies
** Ensure all test steps are clear and executable

# *Status Management*
** Keep test case statuses up to date
** Use "Deprecated" for obsolete test cases
** Only approve test cases that are ready for execution

# *Jira Integration*
** Keep Jira work item status synchronized
** Update status promptly after completion
** Link test execution results to work items

----

h2. Quick Reference Checklist

* (/) Work item is in "In QA" status
* (/) Requirements reviewed
* (/) Test cases reviewed
* (/) Test cases approved (status updated to "Approved")
* (/) Test cases updated (if needed) with versioning
* (/) Execution completed and reviewed
* (/) Sign-off provided (if applicable)
* (/) Jira work item updated to "Ready for UAT"
