h1. Zephyr Test Case Linking Utility - Documentation

h2. Overview

The Zephyr Link Utility allows you to automatically link Zephyr Scale test cases to Jira work items. This utility is optimized for scalability and can handle projects with thousands of test cases efficiently.

h2. Key Features

* *Automatic Test Case Discovery*: Finds test cases by label or name pattern
* *Pagination Support*: Efficiently handles projects with 1000+ test cases
* *Duplicate Prevention*: Skips test cases that are already linked
* *Retry Logic*: Handles Zephyr indexing delays with automatic retries
* *Dry Run Mode*: Preview what would be linked without making changes

h2. Scalability Improvements

The utility has been optimized to handle large projects efficiently:

# *Pagination Support*: Fetches test cases in pages of 1000, avoiding memory issues
# *Streaming Filtering*: Filters test cases during pagination, not after loading all data
# *Early Termination*: Stops pagination when safety limits are reached (10,000 test cases)
# *Efficient Label Search*: Uses exact matching for work item labels to avoid false positives

h3. Performance Characteristics

* *Small Projects (< 1000 test cases)*: Fast, single API call
* *Medium Projects (1000-5000 test cases)*: Efficient pagination, typically 2-5 API calls
* *Large Projects (5000-10000 test cases)*: Handles gracefully with pagination, typically 5-10 API calls
* *Very Large Projects (> 10000 test cases)*: Safety limit prevents excessive API calls

h2. Command Reference

h3. Basic Usage

Link all test cases for a work item:

{code}
npm run zephyr:LinkToJira -- --work-item SF-570
{code}

h3. Link Specific Test Case

Link a single test case by test case ID or Zephyr key:

{code}
# By test case ID (label)
npm run zephyr:LinkToJira -- --work-item SF-570 --test-case SF-570-UI-001

# By Zephyr key
npm run zephyr:LinkToJira -- --work-item SF-570 --test-case SF-T1523
{code}

h3. Dry Run (Preview Mode)

Preview what would be linked without making changes:

{code}
npm run zephyr:LinkToJira -- --work-item SF-570 --dry-run
{code}

h2. How It Works

h3. Search Strategy

The utility uses a two-step search strategy:

# *Label Search*: Searches for test cases with the exact work item label (e.g., "SF-570")
# *Name Pattern Search*: Falls back to searching by name pattern if label search finds no results
## Matches test case names starting with the work item (e.g., "SF-570-UI-001: ...")
## Matches test case ID labels (e.g., "SF-570-UI-001", "SF-570-API-001")

h3. Linking Process

# *Verify Jira Work Item*: Confirms the work item exists in Jira
# *Get Jira Issue ID*: Retrieves the internal Jira issue ID required by Zephyr API
# *Check Existing Links*: Identifies test cases already linked to avoid duplicates
# *Create Links*: Links test cases that aren't already linked

h3. Retry Logic

The utility includes automatic retries to handle Zephyr indexing delays:

* *Default Retries*: 3 attempts
* *Delay Between Retries*: 2s, 4s, 6s (exponential backoff)
* *Use Case*: Newly created test cases may take a few seconds to be indexed

h2. Troubleshooting

h3. No Test Cases Found

If the utility reports "No test cases found", check:

# *Test Cases Exist*: Verify test cases exist in Zephyr Scale UI
# *Labels*: Ensure test cases have the work item label (e.g., "SF-570")
# *Name Pattern*: Test case names should start with the work item (e.g., "SF-570-UI-001: ...")
# *Project Key*: Verify the test cases are in the correct project (default: "SF")
# *Indexing Delay*: Wait a few minutes after creating test cases, then retry

h3. Performance Issues

If the utility is slow:

# *Large Projects*: Projects with 5000+ test cases will take longer due to pagination
# *Network*: Slow network connections will affect API call performance
# *Zephyr API*: Zephyr API response times can vary based on server load

h3. Duplicate Links

The utility automatically skips test cases that are already linked. If you see "Already linked (skipped)" messages, this is expected behavior.

h2. Best Practices

# *Use Dry Run First*: Always run with {{--dry-run}} to preview what will be linked
# *Link After Upload*: Link test cases immediately after uploading them to Zephyr
# *Batch Processing*: For multiple work items, process them one at a time
# *Monitor Performance*: For large projects, monitor the pagination progress in the logs

h2. Technical Details

h3. API Endpoints Used

* {{GET /testcases?projectKey={projectKey}&startAt={startAt}&maxResults={maxResults}}} - Fetch test cases with pagination
* {{GET /issues/{issueId}}} - Get Jira issue details
* {{GET /issues/{issueId}/remotelink}} - Get existing remote links
* {{POST /testcases/{testCaseKey}/links/issues/{issueId}}} - Create link between test case and Jira issue

h3. Environment Variables

* {{ZEPHYR_PROJECT_KEY}}: Project key for Zephyr (default: "SF")
* {{JIRA_BASE_URL}}: Base URL for Jira instance
* {{ZEPHYR_NON_INTERACTIVE}}: Set to "true" for non-interactive mode
