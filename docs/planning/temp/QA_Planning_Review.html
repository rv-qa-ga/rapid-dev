1. Month-end process

Current status

Source: docs/planning/Month-End-Close-Process.pptx

What it is

The month-end close is a critical, recurring operational cycle where Accelerant processes, validates, and reconciles all financial data across multiple systems, regions, and entities — culminating in consolidated financial statements for that month. It runs at the end of each month and involves executing a sequenced set of stored procedures that generate CSV files consumed by downstream finance, reinsurance, and reporting systems.

Teams involved

OperationsStops BDX loading ~1 week before close per the month-end calendar
Production Support (Stacey's team)Runs the month-end process in production every month
Finance (EU / US / CA)Reviews, approves, and posts journal entries to the ledger
Data EngineeringMaintains ODS, TDS, and Data Products pipelines

QA EngineeringTests process changes; validates new insurers and regions

End-to-end system flow

BDX Sources → ADP Ingestion → ODS Enrich → TDS Transform → D365 GL / SL → Tagetik and DCR → Close & Report

QA team’s role in month-end

QA does not run the month-end process in production. Production Support executes it monthly. QA is engaged when changes are made to stored procedures, mappings, or when new insurers / contract types / regions are onboarded.

  • Change testing: Stored procedure modifications; new/updated field mappings; schema or table changes; new fee codes or LOB mappings
  • Output validation: CSV file generation verification; file format & schema compliance; control totals & row counts; data completeness checks
  • New contract type / insurer / region: End-to-end data flow for new entity; reference data alignment (RDM / CMT); downstream system acceptance; DCR mapping validation
  • Test types: Smoke (system readiness); Integration (multi-hop data flows); Regression (monthly validation pack)

Goal: Catch issues before they reach production — reduce multi-day resolution cycles during the live close window.

Business impact

  • Multi-day resolution cycles every month-end close
  • 4 regions (EU, UK, US, CA) all impacted simultaneously
  • 6+ systems (Finance, DCR, Tagetik) blocked downstream
  • Public company reporting deadlines are non-negotiable

Strategic options under evaluation

Short-term, Mid-term, and Long-term options. Long-term includes Re-architecture evaluation: assess complete re-architecture of the stored procedure chain — modernise pipelines to eliminate structural failures.

Automation Runbook – QA Adoption

Audience: Manual QA team members who want to run and use the E2E automation framework. Goal: Checklist to run tests, understand results, and contribute. Recommendation: Use Cursor IDE. Code: GitHub (clone repo).

How to use

  • Work through sections in order; check off each item when done.
  • If something fails, see Troubleshooting below or ask the framework owner.

1. Get the code and tooling

  • 1.1 Install Node.js 18+ (nodejs.org), Git (git-scm.com).
  • 1.2 (Recommended) Install Cursor (cursor.com); open project in Cursor.
  • 1.3 Clone repo: git clone <repository-url>, cd E2EAutomation, then npm install, npm run build.

2. Environment configuration

  • 2.1 Copy src/config/env/env.sample to src/config/env/.env.qa (do not commit).
  • 2.2 Get credentials from your lead (Salesforce, Jira/Zephyr, MuleSoft as needed); fill .env.qa.
  • 2.3 (Optional) npm run connectivity:check

3. Run your first tests

  • 3.1 npm run test:all · UI only: npm run test:ui · API only: npm run test:api
  • 3.2 By work item: npm run test:tag -- --tags @SF-563
  • 3.3 With browser: npm run test:interactive · Reports: reports/ or npm run report:open

4. Basics

  • 4.1 UI tests: src/features/ui/, API: src/features/api/; steps: src/step-definitions/.
  • 4.2 Read README.md; skim docs/framework-documentation.md or Confluence.

5. Cursor and GitHub (recommended)

  • 5.1 Open project in Cursor; branch: git checkout -b your-name/short-description.
  • 5.2 After changes, run relevant test; commit, push, open Pull Request.

Optional: Jira/Zephyr

npm run jira:generate -- SF-600; npm run zephyr:UploadAndLink -- --work-item SF-600; npm run process:new-qa-items. Full steps in docs/planning/AUTOMATION_RUNBOOK_QA_ADOPTION.md.
